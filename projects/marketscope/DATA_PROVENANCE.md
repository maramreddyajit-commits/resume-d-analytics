# Historical data provenance

Chen, D. (2012). Online Retail II [Dataset]. UCI Machine Learning Repository. https://doi.org/10.24432/C5CG6D . Official page https://archive.ics.uci.edu/dataset/502/online+retail+ii lists CC BY 4.0. Access/download: 2026-11-17. Historical UK online gift retailer, December 1, 2009–December 9, 2011; price in GBP. Source timezone unspecified; preserved as local-naive calendar dates, not converted to invented UTC.

Official download: https://archive.ics.uci.edu/static/public/502/online%2Bretail%2Bii.zip . Workbook SHA256 bcbe73b35f5b7babf197fb0cb983a11f5d9ff929078d4aa53d171b1f2df2e980. Zip SHA256 572e36277c2390fbfde10664750731e0a86f55e33470d91919085f0408e67bfb. Both workbook sheets are ingested. Raw rows 1,067,371; curated rows 1,021,127. Raw files, IDs and row-level records remain local and are excluded from Git. Public outputs are aggregates with attribution.

Mutually exclusive exclusions in priority order: 34,335 exact duplicates (all eight source fields); 6,019 invalid/zero-price lines; 5,889 non-merchandise/adjustment lines; 1 inconsistent positive-quantity cancellation. Merchandise stock code rule is five digits followed by zero to two letters. It is an explicit analytical definition, not proof that every excluded code is noncommercial. No margin is inferred.

Raw missing CustomerID: 243,007; retained missing CustomerID: 226,964. These become UNKNOWN and stay in sales totals, but not RFM/cohort calculations. Raw missing descriptions: 4,382; no automatic assumption that these are sales. Cancellation prefix C and negative quantity are both inspected. Accepted negative quantities are returns even without C. Returns are reported as positive absolute values; net=gross−returns. Exact duplicate removal is debatable for legitimate identical order lines; an including-duplicates sensitivity is provided.

Grain: one accepted source invoice line with a unique line_id; distinct positive sale invoice IDs define orders. Fact links to product, date, customer and location dimensions. Product description uses the latest retained description, which can change historically. All money uses integer micro-GBP (price×1,000,000 rounded, then multiplied by integer quantity), avoiding floating aggregation drift. RFM uses known sale customers only and an as-of date of December 10, 2011. December 2011 is partial and omitted from complete-month cohort return calculations; zero-activity mature months are explicitly filled.

Commands: `python scripts/download_retail.py`; `python -m projects.marketscope.src.warehouse`. Local parsed-workbook cache is keyed to the original workbook checksum; delete data/raw.pkl to force an Excel reread. The cache is locally generated, never an externally downloaded pickle. No random seed is used. Historical observations are not current performance, future CLV, available inventory or measured interventions.
